# 工作流：从一次技能加载到一次可信的改进

一页说清这套插件怎么用、谁做什么、什么算"改好了"。机制来源见
[RRSI-NOTES.md](RRSI-NOTES.md)（Google 的 harness 自改进工作），评分口径见
[DETAIL.md](DETAIL.md)，验收见 [ACCEPTANCE.md](ACCEPTANCE.md)。

## 一句话

**加载技能 → 收集真实遥测 → 评分 + 区间 → 只对显著信号出建议 → 改前做泄漏审查 →
改后用区间移动判断是否真变好。** 全程零模型 token（除了 agent 主动调工具时）。

## 流程

```
                     ┌──────────────────────────────────────────────┐
  人 / agent 加载技能  →   recorder 抓窗口：调用/报错/纠正/loop/MCP/token │
                     └───────────────────┬──────────────────────────┘
                                         ↓
                     ┌──────────────────────────────────────────────┐
                     │ 报告：4 维评分 + 95% bootstrap 区间 + 排名显著性   │
                     │      MCP 健康板 · 运行板 · 快照 · 对话结果条        │
                     └───────────────────┬──────────────────────────┘
                                         ↓
                     ┌──────────────────────────────────────────────┐
                     │ 建议：噪声地板（区间未越过阈值 → 降为 info）        │
                     │       token 成本 · 剪枝 · 反触发/引用完整性        │
                     └───────────────────┬──────────────────────────┘
                                         ↓
        /skill-eval loop all  →  按「预期收益 / 改动成本」排序，挑下一个
                                         ↓
                     ┌──────────────────────────────────────────────┐
                     │ skill_eval_review：改前泄漏审查（reject/warn/accept）│
                     │ + 写 ledger：假设、维度、裁决、diff hash          │
                     └───────────────────┬──────────────────────────┘
                                         ↓
                     改技能 → 真实使用几轮 → 复用同一套遥测重新测量
                                         ↓
                     只有「区间移动 + token 不变差」才算改好；否则回滚
```

## 三个角色

| 角色            | 做什么                                                           | 不做什么                                     |
| --------------- | ---------------------------------------------------------------- | -------------------------------------------- |
| **人**          | 决定改哪个技能、判断改动是否合理、批准/回滚                      | 不需要读 JSON、不需要手工算分                |
| **agent（我）** | 调 `skill_eval_report` / `skill_eval_review`，按 loop 计划改文件 | 不自己编造分数；不跳过 review 直接改         |
| **插件**        | 记录、评分、区间、建议、ledger、看板/结果条                      | 不自动改技能、不自动接受改动、不执行技能脚本 |

## 判定规则（避免自欺）

1. **噪声地板**：建议默认只在 95% 区间下端越过阈值时保留 `critical`/`warning`；
   区间还跨阈值 → 降为 `info` 并注明 "not outside noise yet"。
2. **样本不足**：`n < minSamples` 给 `provisional`，不给 CI；此时只提"再测几轮"。
3. **改好没有**：看**区间**是否移动，不看点估计；同时 token 成本不能变差。
4. **预算**：每轮可同时改的条数从 4 退火到 1（按已接受的编辑数），
   避免一次改太多导致无法归因。
5. **探索**：连续 2 次都在改同一维度 → 强制换一个最久没动的维度。
6. **泄漏审查**：写死答案、benchmark 名、task id、机器路径、日期窗口 → 拒/警。

## 常见状态与含义

| 看到                         | 含义                                         | 该怎么办                       |
| ---------------------------- | -------------------------------------------- | ------------------------------ |
| `provisional: true`、无 CI   | 样本 < 3                                     | 正常用，攒样本                 |
| `ranking.significant: false` | 技能区间重叠                                 | 别把排名当结论                 |
| `advice` 全是 `info`         | 没有越过噪声的问题                           | 不用改                         |
| `broken-references`          | 正文承诺的 `references/*`/`scripts/*` 不存在 | 补文件或改路径（critical）     |
| `no-anti-trigger`            | 没写"不适用于"                               | 加一行边界，降低误触发         |
| `prune-candidate`            | ≥6 次加载且分数 <60、区间也低                | 删除或合并                     |
| `token-cost`                 | 单次加载可计费 token 超预算                  | 精简正文 / 后置激活            |
| `UNREACHABLE`（验收脚本）    | 端口变了                                     | 脚本会自动发现；显式传地址即可 |
| `stale generation`           | 宿主跑的是旧模块                             | 重启 DSH                       |

## 日常三条命令

```bash
dsh-skill-eval-accept            # 自检（自动发现 GUI 端口）
/skill-eval loop all             # 下一步该改谁
/skill-eval                      # 全量报告
```

## 边界（诚实清单）

- 有效性是从"下一条用户消息是否为纠正"推断的，不是人工标注
- 子 agent 的窗口不计入 abandon 判定
- 只能看到模型可调用（model-invocable）的技能
- 静态检查读不到原始 frontmatter、也不执行技能脚本
- 样本量小（当前 4 个技能 / 十余次加载），所有结论都带样本数与区间
